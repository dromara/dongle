# Change Log
## [v1.3.0](https://github.com/dromara/dongle/compare/v1.2.3...v1.3.0) (2026-10-19)

### ✨ Features

- **Add ASN.1 ciphertext and signature formats to SM2**: `Sm2CipherMode` gains `ASN1C1C2C3` and `ASN1C1C3C2`, so ciphertext can be encoded as the DER `SEQUENCE { x INTEGER, y INTEGER, C2 OCTET STRING, C3 OCTET STRING }` that BouncyCastle, Java and most national-crypto gateways produce, instead of only the raw `C1 || C2 || C3` / `C1 || C3 || C2` byte layout; `Sm2SingMode` (`ASN1` as the default, `Bytes`) and `SetSingMode` are added so a signature is either a DER `SEQUENCE { r, s }` or a fixed 64-byte `r || s`; both formats are parsed with `cryptobyte`, so a truncated or non-DER payload returns an error instead of being silently misread, and `NewSm2KeyPair` keeps `ASN1` as the default (by [@Web-Coke](https://github.com/Web-Coke) in [#40](https://github.com/dromara/dongle/pull/40))
- **Extend the morse alphabet to the full ITU-R M.1677-1 table and the international extended characters**: adds `¡`, `¿`, `å`/`Å`, `ä`/`Ä`, `é`/`É`, `ñ`/`Ñ`, `ó`/`Ó`, `ö`/`Ö` and `ú`/`Ú` with the codes published by codigomorse.org, documents which ITU section each group comes from, and moves `/` into the punctuation group; **note** that two existing mappings change — `<` moves from `.--.-` to `.--.--` because `.--.-` now belongs to `å`, and `\n` becomes `.-..-..`, which also separates it from `\r`; text encoded with v1.2.3 decodes differently for those two characters (by [@htlsmilework](https://github.com/htlsmilework) in [#42](https://github.com/dromara/dongle/pull/42))

### 🐛 Fixes

- **Fix ascii85 decoding truncating its output when `z` shortcuts are present**: `encoding/ascii85` emits a single `z` for an all-zero four-byte group and the encoder here does the same, but the decoder recomputed the destination length from the character count at a strict 5:4 ratio and truncated the standard library's correct answer to it, so five zero bytes round-tripped to two, and eight zero bytes to one, without any error; `z` is now excluded from the ratio and counted as four bytes, and the destination is sized for the expansion a shortcut implies (by [@youdie006](https://github.com/youdie006) in [#44](https://github.com/dromara/dongle/pull/44))
- **Fix ascii85 decoding failing for four or more zero groups**: the `u` padding still used `len(src)%5` after the length fix above, so with `z` shortcuts present the final group could be left with a single character, which `encoding/ascii85` rejects — sixteen zero bytes, encoded as `zzzz`, did not decode at all; both decoders now pad by the non-`z` length (by [@youdie006](https://github.com/youdie006) in [#47](https://github.com/dromara/dongle/pull/47))
- **Fix base58 and base62 streams producing different output from the bulk API**: both alphabets treat the input as a single big number, so it cannot be split into independent chunks, yet the stream encoder encoded every 8 bytes separately and the stream decoder decoded every 1024 bytes separately — `Encode.FromFile(...).ByBase58()` and `ByBase62()` returned a different result than `FromBytes()` for the same data, and that result did not decode back; the stream encoder now buffers the input and encodes it once in `Close`, as its documentation already described, and the decoder reads all of the encoded input and decodes it once, releasing its buffers as the decoded data is consumed (by [@Shaisolaris](https://github.com/Shaisolaris) in [#48](https://github.com/dromara/dongle/pull/48))
- **Fix key pairs rejecting keys generated by other tools and panicking on a key of the wrong algorithm**: a key was only accepted when it was byte for byte the output of `GenKeyPair`, i.e. a `PUBLIC KEY`/`PRIVATE KEY` PEM block holding PKIX or PKCS#8 DER; the base64 and raw material printed by most SM2 and Ed25519 generators failed with `invalid public key: <nil>` or an unintelligible ASN.1 error, and an RSA key passed to an Ed25519 key pair panicked because the result of the type assertion was never checked ([#41](https://github.com/dromara/dongle/issues/41)); every `Parse*`, `Format*` and `Set*` method now goes through a shared selector that tries the input as PEM, base64 (all four alphabets, with or without padding), hex and bare key material, and lets the algorithm-specific parser pick the interpretation that works — Ed25519 accepts PKIX/PKCS#8 DER, a 32-byte seed and a 64-byte private key, SM2 accepts PKIX/PKCS#8 DER, a 65-byte uncompressed point and a 32-byte scalar, RSA accepts PKIX/PKCS#1 DER; SM2 key formatting now uses a local SPKI/PKCS#8 encoder because `crypto/x509` has no SM2 support, so the output still parses in OpenSSL and Java; `Set*Key` accept PEM and normalize it, a block of another algorithm or direction is rejected before parsing with `UnsupportedKeyFormatError` ("the parsed key is an RSA key, not an Ed25519 key"), the error messages no longer print `<nil>`, `Compress*Key` use `pem.Decode` instead of string surgery so optional headers are handled, and the SM2 private scalar is validated to be in `[1, n-1]` — `d = 0` used to produce a key without a public point (by [@gouguolei](https://github.com/gouguolei) in [012269d](https://github.com/dromara/dongle/commit/012269d4b1b58d58d4f1df3b816d276084cc545d))

### ⚡ Performance

- **Derive the morse reverse alphabet once instead of scanning it per symbol**: `StdDecoder.Decode` ranged over the whole `StdAlphabet` until it found a matching code, making decoding O(n × 89) where it should be O(n) and spending 53% of a CPU profile in map iteration; the inverse map is now built once in `init()`, the way base45 and base91 already derive their decode tables, cutting the geomean by 89.21% (4096 characters: 1222µs → 103µs) with allocations unchanged; the scan also made decoding non-deterministic, because seven codes are shared by an upper- and lower-case pair (`Å`/`å` for `.--.-`, and likewise for `ä`, `é`, `ñ`, `ó`, `ö`, `ú`) and ranging over a map picks a random winner, so `.--.-` decoded to `Å` 62% of the time and encoding-then-decoding those characters was not lossless; the inverse map resolves such collisions to the lower-case form, which is the only one `Encode` can produce (by [@darakanoit](https://github.com/darakanoit) in [#46](https://github.com/dromara/dongle/pull/46))

### 🔧 Refactors

- **Route key serialization through package-level helpers**: `marshalPKIXPublicKey` and `marshalPKCS8PrivateKey` are now variables wrapping `crypto/x509`, and `marshalSm2PublicKey`/`marshalSm2PrivateKey` wrap the local SM2 encoder, so the error branches of `Format*Key` can be simulated in tests, since `crypto/x509` never fails for a key that has already been parsed into its typed form; RSA, Ed25519 and SM2 formatting all use them (by [@gouguolei](https://github.com/gouguolei) in [e314c99](https://github.com/dromara/dongle/commit/e314c992215bc824c8f645e19edc3f29560ddf54) [6ad47b4](https://github.com/dromara/dongle/commit/6ad47b474792c1e13502a5a7fb0df7ab6bf2e920) [0769ea0](https://github.com/dromara/dongle/commit/0769ea0d969de33899ff629a5307e5758e8b2f86) [2c9ad5a](https://github.com/dromara/dongle/commit/2c9ad5a7bc0ff1ea0b2957b910328c33d8c6b98e))
- **Simplify the RSA stream verifier and drop unused stream buffers**: `rsa.StreamVerifier.verify` returns only an `error` instead of a `valid` flag that was always true when the error was nil, `unicode.StreamEncoder` and `unicode.StreamDecoder` lose their unused fixed `[512]byte` buffers, and the morse error message uses a plain string literal instead of `fmt.Sprintf` with no verbs (by [@gouguolei](https://github.com/gouguolei) in [68dad92](https://github.com/dromara/dongle/commit/68dad927bbb23e6c75558a4777f30e206eb99697))
- **Fix an inverted `SetSingMode` assertion and initialize the SM2 default explicitly**: the clamp test expected `SingMode` to stay `ASN1` after `SetSingMode(Bytes)`, which cannot happen because the setter simply assigns, and `NewSm2KeyPair` relied on the zero value being `ASN1`; the constructor now sets `SingMode: ASN1` and the test asserts both directions (by [@gouguolei](https://github.com/gouguolei) in [079efab](https://github.com/dromara/dongle/commit/079efab2892b66028898fe430d0649e41bc7302e))
- **Clean up and extend the test suite**: removes unused variables and duplicated cases from 24 test files, adds `key_format_test.go` and `key_test.go` covering the key material helpers, every `UnsupportedKeyFormatError` message and the rejection paths of the public API, and covers the SM2 DER and private scalar range branches, raising `keypair` statement coverage to 97.7% (by [@gouguolei](https://github.com/gouguolei) in [372209d](https://github.com/dromara/dongle/commit/372209db32677f5b9e8bab6547354196d501c463) [12c3e11](https://github.com/dromara/dongle/commit/12c3e11bf317e7643f932d8e8505bf2a08c6067b))

## [v1.2.3](https://github.com/dromara/dongle/compare/v1.2.2...v1.2.3) (2025-12-16)

### ✨ Features

- **Let an RSA key pair hold only the key its operation needs**: `RsaKeyPair` gains a `Type` field, set through `SetType`, together with the new `KeyType` type and its `PublicKey` / `PrivateKey` constants; `NewStdEncrypter`, `NewStdDecrypter`, `NewStdSigner`, `NewStdVerifier` and their streaming counterparts branch on it, so a key pair carrying only a public key can encrypt and verify and one carrying only a private key can decrypt and sign, and the public key can also be the signing side when a private key is the verifier; an empty `Type` falls back to the sensible side per operation — `PublicKey` for encrypt and verify, `PrivateKey` for decrypt and sign — and the default padding follows the key format, `PKCS1` keys using `PKCS1v15` and `PKCS8` keys using `OAEP` for encryption and `PSS` for signing, with `OAEP` rejected for signing and `PSS` for encryption through `UnsupportedPaddingSchemeError`; the padding for both key sides and every combination is now implemented in `crypto/internal/rsa`, including the PSS encoding and MGF1 that Go's `crypto/rsa` only exposes for one direction (by [@gouguoyin](https://github.com/gouguoyin) in [12ffe48](https://github.com/dromara/dongle/commit/12ffe48) [eb81cbc](https://github.com/dromara/dongle/commit/eb81cbc) [33ac684](https://github.com/dromara/dongle/commit/33ac684) [749b690](https://github.com/dromara/dongle/commit/749b690))
- **Add `SetMode` to `Sm2KeyPair` and rename `CipherOrder` to `Sm2CipherMode`**: `SetMode` becomes the documented way to pick the ciphertext order and `SetOrder` is kept as a thin alias so existing calls still compile; the type rename only breaks code that spelled `CipherOrder` out, and the `order` parameter is renamed to `mode` throughout so it no longer collides with the word used for key ordering (by [@gouguoyin](https://github.com/gouguoyin) in [858d8b8](https://github.com/dromara/dongle/commit/858d8b8) [3785a02](https://github.com/dromara/dongle/commit/3785a02) [6d30805](https://github.com/dromara/dongle/commit/6d30805) [56b6b15](https://github.com/dromara/dongle/commit/56b6b15))

## [v1.2.2](https://github.com/dromara/dongle/compare/v1.2.1...v1.2.2) (2025-12-08)

### ✨ Features

- **Add SM2 signing and verification to the fluent API**: `Signer.BySm2` and `Verifier.BySm2` are added for both standard and streaming processing, so SM2 joins RSA and Ed25519 and a signature can be produced with the private key and checked with the public key in the same chain; `Sm2KeyPair.SetUID` sets the user identity mixed into ZA, which stays `1234567812345678` when unset; verification reports an empty signature as `EmptySignatureError` before any curve arithmetic happens (by [@gouguoyin](https://github.com/gouguoyin) in [b72066e](https://github.com/dromara/dongle/commit/b72066ef089fd58727d321b575b9d16d87d9f211) [0382cd6](https://github.com/dromara/dongle/commit/0382cd6) [39d00c3](https://github.com/dromara/dongle/commit/39d00c3))
- **Add RSA padding scheme selection**: the new `RsaPaddingScheme` type exposes `PKCS1v15`, `OAEP` and `PSS`, chosen with `SetPadding`; `PKCS1v15` works for both encryption and signing, `OAEP` only for encryption and requires a hash set through `SetHash`, `PSS` only for signing; when no padding is set it follows the key format, `PKCS1` keys falling back to `PKCS1v15` and `PKCS8` keys to `OAEP`, and an unsupported combination returns `UnsupportedPaddingSchemeError` instead of an opaque standard-library error (by [@gouguoyin](https://github.com/gouguoyin) in [d1734dc](https://github.com/dromara/dongle/commit/d1734dc) [b4173be](https://github.com/dromara/dongle/commit/b4173be) [d08e5fc](https://github.com/dromara/dongle/commit/d08e5fc))
- **Add separate key and signature error types**: `EmptyPrivateKeyError`, `EmptyFormatError`, `UnsupportedKeyFormatError`, `EmptyPaddingError`, `UnsupportedPaddingSchemeError` and `EmptySignatureError` replace the single catch-all, so a missing key can be told apart from a malformed one (by [@gouguoyin](https://github.com/gouguoyin) in [856dd51](https://github.com/dromara/dongle/commit/856dd51))

### 🐛 Fixes

- **Fix RSA decryption failing for PKCS#1 v1.5 ciphertext when the private key is stored as PKCS#8** ([#39](https://github.com/dromara/dongle/issues/39)): with `Format` set to `PKCS8` and no explicit padding, decryption fell back to OAEP, so data encrypted by JSEncrypt or by PHP's `openssl_*` defaults failed with `crypto/rsa: decryption error` even though PHP itself decrypted it; the padding is now selectable through `SetPadding` and the key pair from the report is kept as a regression test (by [@gouguoyin](https://github.com/gouguoyin) in [27c69f6](https://github.com/dromara/dongle/commit/27c69f6))
- **Remove the redundant signature length check from RSA verification**: the guard rejected signatures produced by other libraries before `rsa.Verify*` had a chance to validate them, while the standard library already reports a clear error for a malformed length (by [@gouguoyin](https://github.com/gouguoyin) in [faa99bb](https://github.com/dromara/dongle/commit/faa99bb))

### ⚡ Performance

## [v1.1.0](https://github.com/dromara/dongle/compare/v1.0.1...v1.1.0) (2025-08-23)

> ⚠️ This is a breaking change version, please upgrade with caution, but it is strongly recommended to upgrade

### ✨ Features

- Add support for `file stream` encoding/decoding, encryption/decryption, Hash/HMAC, signature/verification
- Add new `ByBase32Hex` encoding/decoding method
- Add support for `base32/base32Hex` encoding custom character
- Add support for `base45` encoding custom character
- Add support for `base62` encoding custom character
- Add support for `base64/base64Url` encoding custom character

### 🔧 Refactors

- Delete `BySafeURL` encoding/decoding method
- Delete `Sm3` hash algorithm (`hash`) and message authentication code algorithm (`hmac`)
- Rename `ByBase64URL` encoding/decoding method to `ByBase64Url`
- Hash algorithm (`hash`) calling method changed from `dongle.Encrypt.ByXXX()` to `dongle.Hash.ByXXX()`
- Message authentication code algorithm (`hmac`) calling method changed from `dongle.Encrypt.ByHmacXXX()` to `dongle.Hash.WithKey().ByXXX()`
- Refactor `AES`, `DES`, `3DES`, `Blowfish` and other symmetric encryption/decryption methods, uniformly use `cipher.NewXXXCipher()`
- Refactor `RSA` and other asymmetric encryption/decryption methods, uniformly use `keypair.NewXXXKeyPair()`
